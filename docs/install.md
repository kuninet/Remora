# インストール手順

ビルドした `Remora.app` を日常使いの状態にセットアップする手順をまとめます。

## 1. `/Applications` に配置

Finder で `build/Remora.app` を `/Applications` フォルダにドラッグ&ドロップします。

CLI でも可:

```bash
./scripts/install.sh
```

## 2. 初回起動時の Gatekeeper 対応

署名・Notarization をしていないため、`/Applications/Remora.app` をダブルクリックすると次のようなダイアログが出ます。

> "Remora" は、開発元を検証できないため開けません。

これは個人ビルドアプリの仕様です。以下のいずれかで解決します。

### 方法 A: 右クリック → 開く (推奨)

1. Finder で `/Applications/Remora.app` を **右クリック (control + クリック)**
2. メニューから「開く」を選択
3. 同様のダイアログが出るが、今度は「開く」ボタンが有効になっているのでクリック

以降は通常通りダブルクリックで起動できます。

### 方法 B: システム設定から許可

1. 一度ダブルクリックでブロックされた状態にする
2. システム設定 → プライバシーとセキュリティ
3. 「"Remora" は確認されていない開発元のため、使用がブロックされました」の右の「このまま開く」をクリック

## 3. 共有フォルダの登録

1. メニューバーの Remora アイコンをクリック
2. **「設定…」** を選択
3. 「共有」タブで **「追加」** ボタンをクリック
4. 以下を入力:
   - ホスト: Windows PC の IP アドレスまたはホスト名 (例: `192.168.1.10`)
   - 共有名: Windows 側で公開している共有名 (例: `shared`)
   - ユーザー名: Windows のユーザー名
   - パスワード: Windows のパスワード (Keychain に保管されます)
   - マウント先: `/Volumes/<共有名>` がデフォルト
5. 「保存」
6. 1 分以内に自動でマウントされます。Finder で `/Volumes/<共有名>` が見えれば成功

複数の共有を登録できます。

## 4. 初回マウント時に表示されるダイアログ

共有を登録して初めてマウントが走るとき、以下のダイアログが順に出ることがあります。事前に流れを把握しておくと迷いません。

### 4.1. macOS の SMB 接続ダイアログ

`/Volumes/<共有名>` への初回マウント時に、macOS 標準の「サーバへ接続」「ユーザ名とパスワードを入力」のようなダイアログが出ることがあります。

- 「**パスワードをキーチェーンに保管**」(または「このパスワードを保存」) のチェックを **必ず入れる**
- 「接続」をクリック

これでシステム側のキーチェーンにも資格情報が記録され、以降のマウントが静かになります。

### 4.2. キーチェーンアクセス許可ポップアップ

Remora がパスワード項目を読み出すタイミングで、次のようなダイアログが出ます。

> "Remora" が、キーチェーン項目 "192.168.1.10/shared" にアクセスしようとしています。許可しますか?

**「常に許可」を選んでください**。「許可」だけだとマウント試行のたびに再表示されてしまいます。

### 4.3. 通知許可リクエスト失敗ログ

起動時にログへ次の NOTICE が 1 行記録されますが、**気にしなくて OK** です。

```
[NOTICE] [general] 通知許可リクエスト失敗: The operation couldn't be completed. (UNErrorDomain error 1.)
```

未署名アプリのため macOS の通知システムが許可ダイアログすら出してくれない、という macOS の仕様です。アプリの動作には影響なく、マウント状態はメニューバーアイコンの色で確認できます。

### 4.4. リビルドして上書きしたあと

`./scripts/make-app.sh` で `.app` を作り直して `/Applications` に上書きすると、macOS から見ると「別アプリ」と判定されて 4.2 のキーチェーンアクセス許可ポップアップが再び出ることがあります。同じく「常に許可」で対処してください (個人ビルド運用の宿命です)。

## 5. 休止時間帯の設定 (任意)

夜間など、リトライしてほしくない時間帯がある場合:

1. 設定ウィンドウの「休止時間帯」タブ
2. 「追加」で時刻範囲を登録 (例: 開始 `23:00`、終了 `07:00`)
3. 複数登録可能。日跨ぎ (23 時-翌 7 時など) も対応
4. 休止時間帯中はメニューアイコンがグレー化し、マウント試行は行われません

## 6. ログイン時の自動起動

メニュー → **「ログイン時に自動起動」** をクリックしてチェック状態にすると、次回ログインから Remora が自動で起動します。

> 内部では `SMAppService.mainApp.register()` を呼んでいます。システム設定 → 一般 → ログイン項目で確認・解除も可能です。

## 7. アイコンの読み方

| アイコン | 意味 |
|---|---|
| 通常色 (`externaldrive.connected.to.line.below`) | 登録されている全共有がマウント済み |
| 黄 (`externaldrive.badge.exclamationmark`) | 一部がマウントされていない (リトライ中) |
| 赤 (`externaldrive.badge.xmark`) | すべての共有がマウントに失敗 |
| グレー (`externaldrive.badge.minus`) | 休止時間帯中 |

## アンインストール

```bash
# 1. アプリ終了 (メニュー → "Remoraを終了")
# 2. ログイン項目から除外: 設定ウィンドウのトグル OFF、もしくはシステム設定から手動で
# 3. .app の削除
rm -rf /Applications/Remora.app

# 4. 設定とログを消す場合 (任意)
rm -rf ~/Library/Application\ Support/Remora

# 5. Keychain からパスワードを消す場合 (任意)
# Keychain Access.app → "Remora" を検索して削除
```
